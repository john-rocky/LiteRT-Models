Thanks for the NPU accelerator path in 2.2.0 — the JIT compile-and-cache flow works exactly as documented, and it is what made this measurement series possible.

While moving my converted vision transformers from GPU to NPU, the single biggest latency factor turned out to be how the GELU is written, not the architecture. Models that hand-write the tanh approximation (`0.5x(1+tanh(0.79788(x+0.044715x³)))` — common in GPU-oriented conversions and in model repos) lower faithfully to a TANH/MUL chain. On Hexagon that chain runs about 2x slower end-to-end than the same model with the builtin GELU op. `F.gelu(approximate='tanh')` already lowers to `GELU(approximate=True)`, which is numerically identical to the chain — so a converter-side fusion of the hand-written pattern into that op looks like a numerics-preserving ~2x for NPU users. Would litert-torch take a PR for that pattern? Happy to write it.

What I measured (Galaxy S26 / SM8850, Hexagon v81, LiteRT `CompiledModel` 2.2.0, on-device JIT, one accelerator per process, N=50 medians, every row at thermal status NONE):

- Real models, one variable (the GELU), official weights: DINOv2-S 85.9 → 41.9 ms (features corr 0.999992), TIPSv2-B14-DPT 326.9 → 142.0 ms (outputs corr 0.99998+). The same swap does not move the Adreno GPU (54.7 ↔ 55.2 ms and 282.5 ↔ 273.3 ms), and both graph forms compile fully onto the NPU in a single partition — no fallback involved.
- A matched-compute probe isolates the pattern: the same 4-block transformer runs 9.4 ms with sigmoid-GELU and 53.8 ms with the tanh chain. Rewriting only `tanh(y)` as `2σ(2y)−1` inside the otherwise identical chain gives 22.1 ms, so the cost is the decomposed pattern itself, not any one kernel.
- Numerics of the proposed fusion: on the real DINOv2-S build, the chain vs `GELU(approximate=True)` differ by max_abs 9e-05 (corr 1.00000000) — the same math. The 41.9/142.0 ms rows above are `approximate=False`; the `approximate=True` build is ready and I will add its latency in a follow-up comment.

Links: probe generator with all numbers in [this gist](https://gist.github.com/john-rocky/374549f4e3dcdd356daafb36c0df135c); the two real-model pairs are published with reproduction steps on their cards, [litert-community/DINOv2-ViT-S14-LiteRT](https://huggingface.co/litert-community/DINOv2-ViT-S14-LiteRT) and [litert-community/TIPSv2-B14-DPT-LiteRT](https://huggingface.co/litert-community/TIPSv2-B14-DPT-LiteRT).

If the fusion belongs elsewhere, or is intentionally absent, the measurements may still be useful as accelerator data. Thanks again for the NPU path — it changed which accelerator I ship on.
